# Contributing to Tucknote

Use Issues for bug reports and feature ideas. For a substantial change, open an issue first so we can agree on the use case and scope. See [SECURITY.md](SECURITY.md) for vulnerabilities.

Fork the repository, create a branch, and open a pull request against `main`. Explain the workflow affected and how you verified the change. On Apple Silicon, run `./build.sh` and `./Tools/test.sh` before opening the PR. For changes to capture, storage, permissions, or link fetching, describe the behavior on existing installs too.

Maintainers triage issues by reproducibility, impact, and scope. A feature request can be accepted, deferred, or closed with a short explanation. A maintainer reviews the code and passing checks before merging. Contributions are licensed under the project's [MIT License](LICENSE).
